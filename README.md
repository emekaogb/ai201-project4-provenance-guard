# Provenance Guard: AI/Human Content Attribution System

A system that analyzes text submissions to classify whether content was written by humans or generated by AI, with transparent confidence scoring and an appeals workflow for creators.

---

## How It Works

### Submission Flow
When a creator submits text via `POST /api/content/submit`, the system:

1. **Validates input** (text 5-5000 characters, creator_id required)
2. **Runs Signal 1: Perplexity Analysis** — measures word-level predictability using a pre-trained GPT-2 model
3. **Runs Signal 2: Linguistic Features** — analyzes 4 stylometric metrics
4. **Combines scores** using weighted average: `finalScore = (0.6 × perplexity) + (0.4 × linguistic)`
5. **Calculates confidence** as distance from decision boundary: `confidence = 2 × |finalScore - 0.5|`
6. **Classifies result** (human/ai/uncertain) based on score and confidence thresholds
7. **Generates transparency label** — one of three variants, chosen based on classification and confidence
8. **Logs everything** to persistent audit trail with both signal scores, classification, and metadata
9. **Returns response** with submission_id, classification, confidence, signals, and label

### Appeal Flow
If a creator disagrees with the classification, they submit an appeal via `POST /api/appeals/submit` with:
- Original submission ID
- Creator identifier
- Reasoning (50-1000 characters)
- Optional evidence URL

The system appends the appeal to the original submission's audit record and marks the submission as "under_review". The appeal awaits human review (future milestone).

## Detection Signals: Design & Rationale

### Signal 1: Perplexity Analysis

**What it measures:** How "surprising" each word is to a pre-trained language model.

**How it works:**
- Uses GPT-2 to calculate perplexity: a measure of how likely the model considers the word sequence
- Lower perplexity (0.0-0.3) → text is predictable, statistically smooth → suggests AI
- Higher perplexity (0.7-1.0) → text is varied, unexpected word choices → suggests human

**Why chosen:**
- **Efficiency**: Computationally fast (single forward pass through model)
- **Generality**: Works across domains without retraining
- **Orthogonal to linguistics**: Captures statistical patterns independent of style
- **Well-calibrated**: GPT-2 perplexity is a well-studied metric with established baselines

**What it misses (blind spots):**
- **Formal human writers**: A researcher writing an abstract will score low on perplexity (predictable vocabulary) just like AI
- **Short text**: Text <50 words has high variance in perplexity and is unreliable
- **Domain-specific text**: Jargon-heavy text (medical journals, legal documents) may have high perplexity regardless of authorship if the model wasn't trained on that domain
- **Human-edited AI**: If someone rewrites an AI draft, the edits introduce perplexity variation

**How we test it:**
Validate on human-written text (published articles, blog posts) and AI-generated text (from GPT-3/4), checking that perplexity distributions are significantly different and that high-confidence predictions have >85% accuracy.

### Signal 2: Linguistic Features

**What it measures:** Stylistic patterns in how sentences are constructed, vocabulary is chosen, and discourse evolves.

**How it works:**
Extracts and combines 4 metrics:

1. **Sentence length variance** (30% weight)
   - AI: uniform sentence length (40-60 words, tight range)
   - Humans: wildly varied (5-word fragments to 80-word runs)
   - Normalized to 0-1 by comparing against typical variance (0-1.5)

2. **Type-token ratio** (40% weight) — vocabulary diversity
   - AI: reuses vocabulary (e.g., "model" appears 15 times in 200 words)
   - Humans: use synonyms and varied word choices (e.g., "model", "system", "approach" used interchangeably)
   - Direct metric: unique_words / total_words, ranges 0.3-0.9

3. **Discourse marker frequency** (20% weight)
   - AI: uses formal markers systematically ("Furthermore", "Moreover", "In conclusion")
   - Humans: use them naturally when needed, much less frequently
   - Counts formal markers per 100 words, scaled to 0-1

4. **Punctuation diversity** (10% weight)
   - AI: limited punctuation types (mostly periods, commas)
   - Humans: varied punctuation (dashes, ellipses, exclamation marks, parentheses)
   - Counts how many distinct punctuation types appear, scaled to 0-1

**Why chosen:**
- **Orthogonal to perplexity**: Captures style/structure, not statistical predictability
- **Hard to fake**: Changing sentence structure requires understanding natural variation
- **Domain-aware**: Works across domains without retraining; adapts to local stylistic baselines
- **Interpretable**: Each metric has clear linguistic meaning; explainable to creators

**What it misses (blind spots):**
- **Non-native English speakers**: May write with formal structure and fewer punctuation variations, scoring like AI
- **Academic writing**: Researchers use formal discourse markers naturally; abstracts score AI-like
- **Repeated content intentionally**: Poetry with repetition, manifesto-style text scores as AI
- **AI trained on casual data**: ChatGPT fine-tuned on Reddit/Twitter learns varied sentence length and informal punctuation
- **Short text**: <50 words provides insufficient data to calculate meaningful variance

**How we test it:**
Generate linguistic profiles for human-written corpus and AI-generated samples, verify that high-scoring human text has significantly different profiles than low-scoring AI text, and check that mismatches (formal humans, casual AI) produce uncertain classifications.

### Why Two Signals?

Single signals are unreliable. With two independent signals:

**Agreement strengthens confidence:**
- Both high → definitely human
- Both low → definitely AI

**Disagreement triggers uncertainty:**
- High perplexity, low linguistics → human who writes formally
- Low perplexity, high linguistics → AI trained on casual data
- System says "uncertain" → honest about ambiguity

**Diversity reduces gaming:**
An AI system could learn to mimic human perplexity (using rare vocabulary) but wouldn't necessarily change its sentence structure. Two orthogonal signals are harder to fool together.

## Confidence Scoring: Why This Approach

### The Problem With Binary Classification

A simple "AI" or "Human" label is false confidence. Reality is messy: some writing is genuinely ambiguous, some signals disagree, and the model's certainty matters.

### Our Solution: Confidence = Distance from Boundary

We use the distance from the 0.5 decision boundary as a proxy for confidence:

```
confidence = 2 × |finalScore - 0.5|
```

**Why this works:**
- **Intrinsic to the math**: A score of 0.95 is very different from 0.50 in information content
- **Calibrated**: Confidence 0.0 means we're completely uncertain, 1.0 means absolute certainty
- **Meaningful labels**: Confidence 0.8 produces a different label ("high confidence") than confidence 0.2 ("low confidence")

**Decision thresholds:**
```
IF finalScore > 0.75 AND confidence > 0.6:
    classification = "human"

IF finalScore < 0.25 AND confidence > 0.6:
    classification = "ai"

ELSE:
    classification = "uncertain"
```

The 0.6 confidence threshold ensures we only make strong claims when both signals push in the same direction.

### Example 1: High-Confidence Human Text

**Input:**
```
"Honestly, I can't believe what happened yesterday. My friend Sarah—who NEVER 
complains—was absolutely furious about how the coffee place got her order wrong. 
I mean, they put oat milk in it and she's allergic to oats! Who makes that mistake?"
```

**Results:**
- Signal 1 (Perplexity): 0.82 (human — varied vocabulary, unexpected phrasing)
- Signal 2 (Linguistic): 0.77 (human — varied sentence length, natural punctuation with dashes)
- Final Score: (0.6 × 0.82) + (0.4 × 0.77) = 0.49 + 0.31 = **0.80**
- Confidence: 2 × |0.80 - 0.5| = **0.60** ✓ (exactly meets threshold)
- **Classification: HUMAN** (score 0.80 > 0.75 ✓, confidence 0.60 > 0.6 ✓)

**Label displayed:** "✓ Likely written by a human" (high confidence)

### Example 2: Lower-Confidence Case

**Input:**
```
"The implementation of machine learning models represents a significant advancement 
in computational systems. Furthermore, the results demonstrate consistent performance 
across diverse datasets. In conclusion, the methodology provides robust validation 
of the proposed approach."
```

**Results:**
- Signal 1 (Perplexity): 0.58 (moderately formal, but varied word choice)
- Signal 2 (Linguistic): 0.42 (formal structure, frequent discourse markers)
- Final Score: (0.6 × 0.58) + (0.4 × 0.42) = 0.35 + 0.17 = **0.52**
- Confidence: 2 × |0.52 - 0.5| = **0.04** (very low)
- **Classification: UNCERTAIN** (confidence 0.04 < 0.6 ✗)

**Label displayed:** "? We're unsure about the authorship" (low confidence, mixed signals)

**Why lower confidence?** Signals disagree: perplexity says "moderately human" (varied vocabulary), but linguistics says "AI-like" (formal structure). This is exactly the case where a creator should be able to appeal — formal human writing triggers this pattern.

## Transparency Labels: Three Variants

### Variant 1: High-Confidence Human

```
✓ Likely written by a human

We're highly confident this content was written by a person.

How we detected this:
The writing shows natural variation in sentence structure and vocabulary 
choices that are typical of human authorship. The text uses diverse 
sentence lengths and includes natural discourse patterns.
```

**When displayed:** Classification is "human" AND confidence > 0.6

**Tone:** Affirming, clear, avoids alarmism

### Variant 2: High-Confidence AI

```
⚠ Likely generated by AI

We're highly confident this content was generated by an AI system, 
not written by a human.

How we detected this:
The text shows patterns of predictability and structural consistency 
that are typical of AI-generated content. Sentences have uniform length 
and structure, with formal discourse markers appearing systematically.
```

**When displayed:** Classification is "ai" AND confidence > 0.6

**Tone:** Cautionary (⚠ icon), informative, not accusatory

### Variant 3: Uncertain

```
? We're unsure about the authorship

Our analysis suggests this content has characteristics of both human 
and AI writing.

This might mean:
• The content is a blend of human and AI (e.g., AI draft revised by a human)
• The writing style is unusual for our detection system
• The author writes in a very formal or mechanical way
• The text is too short for reliable analysis

If you're the creator and this is your original work, you can appeal 
this classification.
```

**When displayed:** Classification is "uncertain" OR confidence ≤ 0.6

**Tone:** Honest about limitations, invites creator action through appeals

## Known Limitations

### Limitation 1: Formal Human Writers Score as Uncertain or AI

**Specific scenario:** A researcher writes an academic abstract or a lawyer writes a legal brief.

**Why it happens:**
- Signal 1 (Perplexity) expects human text to have varied vocabulary, but domain experts use consistent terminology ("model", "liability", "jurisdiction")
- Signal 2 (Linguistics) detects uniform sentence length, low discourse marker frequency → flags as AI
- The two signals disagree → "uncertain" classification

**This is structural:** Fixing it without breaking other cases is hard. We'd need to detect domain-specific text and adjust baselines, which adds complexity and new failure modes.

**Mitigation in current system:** Low confidence triggers "uncertain" label, which explains the ambiguity to the creator and invites appeal.

### Limitation 2: Short Text (<50 Words) Is Unreliable

**Specific scenario:** A tweet, product description, or social media bio.

**Why it happens:**
- Signal 1: High variance in perplexity; 10-word samples don't provide enough context for reliable prediction
- Signal 2: Insufficient data to calculate meaningful variance; a 20-word sentence is "uniform" by default
- Both signals return 0.5 (neutral) for text <3 words

**This is mathematical:** Confidence scoring depends on having enough signal data to compute meaningful statistics.

**Mitigation:** System returns "uncertain" for short text, which is honest. Creators of short content should understand that this system isn't designed for their use case.

### Limitation 3: AI Trained on Human-Written Casual Text

**Specific scenario:** An AI system fine-tuned on Reddit, Twitter, or forum discussions.

**Why it happens:**
- Such models learn varied sentence length, informal punctuation, and casual vocabulary from training data
- Signal 1 (Perplexity): High, because the model predicts casual phrasing
- Signal 2 (Linguistics): High, because sentence structure varies naturally
- System classifies as "human"

**This is inherent to the approach:** If AI systems are trained to mimic human writing, they'll be indistinguishable from humans on these signals.

**Mitigation:** This would require training signals specifically on outputs from known fine-tuned models (e.g., "ChatGPT-trained-on-Reddit"), which is beyond scope here.

## Spec Reflection

### How the Spec Guided Implementation

**Confidence = Distance from Boundary**

The planning document's explicit formula `confidence = 2 × |finalScore - 0.5|` eliminated ambiguity. Instead of debating "what is confidence?", we had a clear mathematical definition. This let us:
- Design the thresholds (0.75 for score, 0.6 for confidence) knowing exactly what they meant
- Test whether confidence was meaningful (high confidence should correlate with accuracy)
- Explain the system to users in concrete terms

**Two Explicit Signal Descriptions**

Knowing the exact properties each signal measures (perplexity = word-level predictability, linguistics = stylistic variation) meant we could:
- Reason about where they'd fail (formal human writers)
- Design them to be orthogonal (reducing redundancy)
- Combine them thoughtfully instead of arbitrarily

### How We Diverged (and Why)

**Divergence: Signal 2 weights changed based on testing**

The planning document suggested equal weighting for Signal 2's submetrics. In implementation, we learned:
- **Type-token ratio** (vocabulary diversity) was the strongest signal of AI vs. human (40% weight)
- **Sentence length variance** was second (30% weight)
- **Discourse markers** and **punctuation diversity** were weaker (20% and 10%)

**Why we changed:** Testing on known AI and human text showed this distribution gave better calibration. The spec's framework (multi-metric, weighted combination) was right; the specific weights needed adjustment.

**Divergence: Appeal endpoint is simpler than spec suggested**

The planning document mentioned "Automated re-classification is not required" but implied the system should support it architecturally. We kept the data structure ready (appeals array with status field) but didn't implement the review/resolution logic.

**Why we simplified:** The spec's goal was transparent appeals logging, not automated workflows. We achieved that. Future extensions would add human review, but that's out of scope for Milestone 5.

## API Endpoints

### Submission Endpoint
```
POST /api/content/submit

Request:
{
  "text": "string (1-5000 characters)",
  "creator_id": "string"
}

Response (200):
{
  "submission_id": "uuid",
  "classification": "human|ai|uncertain",
  "confidence_score": 0.0-1.0,
  "signals": {
    "perplexity": 0.0-1.0,
    "linguistic": 0.0-1.0
  },
  "transparency_label": {
    "title": "string",
    "description": "string",
    "confidence_level": "high|medium|low"
  },
  "timestamp": "ISO-8601"
}

Rate limit: 100 per hour per IP
```

### Appeal Endpoint
```
POST /api/appeals/submit

Request:
{
  "content_id": "submission-id",
  "creator_id": "string",
  "reasoning": "string (50-1000 characters)",
  "evidence": "optional URL"
}

Response (200):
{
  "appeal_id": "uuid",
  "content_id": "original-submission-id",
  "status": "under_review",
  "submitted_at": "ISO-8601",
  "message": "Your appeal has been received..."
}

Errors:
- 400: Invalid input
- 404: content_id not found
- 409: Appeal already exists
```

### Audit Log Endpoints
```
GET /api/log?limit=10&offset=0&classification=human&from=2026-06-30&to=2026-07-01
Response: { "entries": [...], "count": 10 }

GET /api/log/text?limit=10
Response: Plain text formatted log
```

- Proper singleton pattern (model loaded once, reused)
- Log-scale normalization with empirical bounds (min=10, max=200)
- Edge case handling (very short text returns 0.5, errors return neutral)

**What I revised:**

- Added more detailed logging to see what raw perplexity values the model was producing

**Verdict:** Excellent. The agent understood the semantic meaning ("human text has varied vocabulary") and implemented it correctly.

**What I asked:** Generate a function extracting 4 stylometric metrics (sentence length variance, type-token ratio, discourse markers, punctuation diversity), combine them into a 0-1 score where 0=AI and 1=human.

**What it produced:**
- Separate functions for each metric with clear variable names
- Sensible normalization for each (coefficient of variation for sentence length, direct ratio for vocabulary, etc.)
- Weighted combination with 30/40/20/10 split

**What I revised:**
- Verified the weights made sense; they did (type-token ratio was indeed the strongest signal in testing)
- Added comments explaining the linguistic reasoning behind each metric

**Verdict:** The agent delivered a multi-metric system that was interpretable and worked well. The modular structure made testing and debugging straightforward.

### Instance 3: Confidence Scoring Logic Verification

**Verdict:** The agent followed the spec precisely. No revision needed; the implementation was a direct translation of the mathematical definition.

## Testing Approach

### Validation Tests
- **High-confidence human:** Casual text with varied vocabulary and punctuation → both signals high → classification "human"
- **Uncertain case:** Formal human writing → signals disagree → low confidence → "uncertain" label
- **Appeal submission:** Created appeal via endpoint → checked audit log for "under_review" status

### Calibration Tests
- Verified confidence scores are meaningful: high confidence should correlate with accuracy
- Confirmed all three label variants are reachable (not just one)
- Checked that confidence varies meaningfully between different inputs

### Rate Limiting
- Verified 100 per hour limit is enforced
- Checked that X-RateLimit headers are returned correctly

## Questions?

This system is experimental and educational. It demonstrates how to build a multi-signal classification system with transparent decision-making and appeals. For production use, you'd want:
- More extensive calibration on diverse datasets
- Human review of appeals
- Monitoring of false positive/negative rates
- Clear legal disclaimers about accuracy limits
