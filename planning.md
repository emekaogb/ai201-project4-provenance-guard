# Provenance Guard - Planning Document

## Project Overview

Provenance Guard is an AI/human content attribution system. Users submit text; the system returns a classification (human/AI/uncertain) with a confidence score and a plain-English transparency label.

---

## 1. Detection Signals

**Signal 1: Perplexity Analysis**
- **Measures:** How predictable the text is to a pre-trained language model (word-level surprise)
- **Method:** Use GPT-2 or similar to calculate perplexity; lower perplexity → AI pattern, higher perplexity → human pattern
- **Output:** Score 0–1 (0 = AI, 1 = human)
- **Why:** AI text is statistically predictable; human text contains unexpected word choices

**Signal 2: Linguistic Features**
- **Measures:** Stylistic patterns (sentence length variance, vocabulary diversity, discourse markers, punctuation)
- **Method:** Extract metrics (avg sentence length, type-token ratio, marker frequency); compare against human/AI baselines
- **Output:** Score 0–1 (0 = AI characteristics, 1 = human characteristics)
- **Why:** AI uses uniform sentence length and formal structure; humans vary wildly

**Combination:**
```
finalScore = (0.6 × perplexityScore) + (0.4 × linguisticScore)
```
- Perplexity weighted 60% (more reliable cross-domain)
- Linguistic weighted 40% (domain-dependent, but catches what perplexity misses)

---

## 2. Uncertainty Representation

**What a confidence score of 0.6 means:**
The system is moderately confident in its decision. The actual classification is 60% likely to be correct based on the distance from the decision boundary (0.5). A reader should take the label seriously but not as absolute.

**Score mapping:**
```
finalScore = weighted average of signals (0.0–1.0)

confidence = 2 × |finalScore - 0.5|
  → Ranges from 0 (at 0.5) to 1.0 (at 0.0 or 1.0)
  → Example: finalScore 0.75 → confidence = 2 × 0.25 = 0.5
  → Example: finalScore 0.95 → confidence = 2 × 0.45 = 0.9
```

**Decision thresholds:**
```
IF finalScore > 0.75 AND confidence > 0.6:
  classification = "human"

IF finalScore < 0.25 AND confidence > 0.6:
  classification = "ai"

OTHERWISE:
  classification = "uncertain"
```

**In plain terms:**
- **0.75–1.0, confidence >0.6:** Likely human
- **0.25–0.75 OR confidence ≤0.6:** Uncertain
- **0.0–0.25, confidence >0.6:** Likely AI

## 3. Transparency Label Variants

### High-Confidence Human
```
✓ Likely written by a human

We're highly confident this content was written by a person.

How we detected this:
The writing shows natural variation in sentence structure and vocabulary 
choices that are typical of human authorship. The text uses diverse 
sentence lengths and includes natural discourse patterns.
```

### High-Confidence AI
```
⚠ Likely generated by AI

We're highly confident this content was generated by an AI system, 
not written by a human.

How we detected this:
The text shows patterns of predictability and structural consistency 
that are typical of AI-generated content. Sentences have uniform length 
and structure, with formal discourse markers appearing systematically.
```

### Uncertain
```
? We're unsure about the authorship

Our analysis suggests this content has characteristics of both human 
and AI writing.

This might mean:
• The content is a blend of human and AI (e.g., AI draft revised by a human)
• The writing style is unusual for our detection system
• The author writes in a very formal or mechanical way
• The text is too short for reliable analysis

If you're the creator and this is your original work, you can appeal 
this classification.
```

## 4. Appeals Workflow

**Who can submit an appeal:**
The creator of the content (identified by creatorId). Anyone can claim to be the creator; no authentication required at this stage.

**What information they provide:**
- `submissionId`: The original submission ID from the classification response
- `creatorId`: Their identifier
- `reasoning`: 50–1000 characters explaining why they disagree (e.g., "This is my original poem from my blog")
- `evidence` (optional): URL or reference to corroborating evidence

**What the system does when an appeal arrives:**
1. Validate the appeal (check reasoning length, verify submissionId exists)
2. Generate appealId
3. Append appeal object to the original submission's appeals array
4. Update original submission status from "completed" to "under_review"
5. Log the appeal with timestamp
6. Return appealId and "under_review" status to the creator

**What a human reviewer sees:**
When reviewing the appeal queue, a reviewer opens an appeal and sees:
- Original content (full text)
- Original classification (human/AI/uncertain) and confidence score
- Both signal scores (perplexity and linguistic)
- Creator's appeal reasoning and evidence
- Timestamp of both original submission and appeal
- Full audit trail (no manual review yet, but the structure is ready)

The reviewer can then:
- Read the original content + signals
- Consider the creator's claim
- Decide: overturn classification, uphold, or mark as inconclusive
- Log resolution (future milestone)

## 5. Anticipated Edge Cases

**Edge Case 1: Formal human writer (academic, lawyer, technical writer)**
- Scenario: A researcher writes an abstract with uniform sentence length, formal vocabulary, and minimal variation in discourse patterns
- Problem: Both signals may score it as AI (rigid structure, low novelty in word choice)
- Mitigation: Low confidence flag triggers "uncertain" rather than "AI"; creator can appeal and provide publication/institutional evidence

**Edge Case 2: AI text that was heavily revised by a human**
- Scenario: Someone uses ChatGPT to generate a draft, then rewrites 50% of it with personal anecdotes, varied sentence structure, and conversational tone
- Problem: Perplexity signal scores high (human edits introduced variation), but linguistic signal scores medium-to-high (some AI structure remains)
- Mitigation: Signals disagree → "uncertain" classification, which is honest. If confident human classification occurs, it's not a misfire—the human contribution was substantial.

**Edge Case 3: Very short text (< 50 words)**
- Scenario: A single sentence or two-sentence submission
- Problem: Both signals are unreliable on short text (high variance, not enough data to analyze)
- Mitigation: System should handle gracefully—likely returns "uncertain" because confidence is very low

**Edge Case 4: Highly repetitive human text (poem, chant, tongue twister)**
- Scenario: A poem with intentional repetition: "I came, I saw, I conquered. I came, I saw, I conquered."
- Problem: Low type-token ratio and uniform patterns score like AI
- Mitigation: Perplexity may score it as human (word choice is unusual/creative), linguistic as AI (repetition); signals disagree → "uncertain" or low confidence → honest label

### Flow Narrative

**Submission flow:** When a user POSTs text, the system rate-limits the request, validates input, and passes the text to two independent signal analyzers running in parallel. Signal 1 (Perplexity) calculates how predictable the vocabulary is. Signal 2 (Linguistic Features) calculates how varied the writing structure is. A Confidence Scorer combines both signals using weighted averaging, calculates a confidence value based on distance from the decision boundary (0.5), and classifies the result as human/AI/uncertain. The Label Generator selects one of three transparency labels based on the classification. The Audit Logger records all scores, the label, and metadata. The response returns to the user with the classification, confidence score, individual signal scores, and the transparency label.

**Appeal flow:** When a creator disputes a classification, they submit an appeal with their reasoning and optional evidence. The system validates the appeal, generates an appealId, appends the appeal to the original submission's audit record, updates the submission status to "under_review", and returns confirmation. The appeal awaits manual human review (future milestone), during which a reviewer can access the original content, all signal scores, the creator's reasoning, and decide whether to overturn or uphold the classification.

## API Endpoints

### Submission
- **POST /api/content/submit** → submissionId, classification, confidenceScore, signals, transparencyLabel
- **GET /api/submissions/{submissionId}** → retrieve previous submission

### Appeals
- **POST /api/appeals/submit** → appealId, status: "under_review"
- **GET /api/appeals/{appealId}** → appeal status and details

### Audit Log
- **GET /api/log** (query params: limit, offset, classification, from, to) → paginated log entries
- **GET /api/log/text** → same data, human-readable format

### Rate Limiting
- All endpoints limited to 100 requests/hour per IP
- Response headers: X-RateLimit-Remaining, X-RateLimit-Reset
